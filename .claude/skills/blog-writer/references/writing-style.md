# 写作风格指南

提炼自博客现有文章，代表作：`content/Linux/sizeof vs strlen：从一次 fwrite 踩坑说起.md`。

## 标题

- 正文从 `## 1` 开始（first-level 2）。原因：Quartz 把 frontmatter 的 `title` 渲染成页面 h1，正文再用 `#` 会和它冲突。
- 子节用 `### 1.1`，最多 3 级（`#`/`##`/`###`）。
- 编号连续清晰，配合 `number headings` 插件自动生成目录。

## 代码

- 标注语言（```c、```bash、```yaml 等）。
- 关键行加**中文注释**。
- 错写法和对写法**放一起对比**，读者一眼看出差别：

```c
// 错误写法
fwrite(write_buf, sizeof(char), sizeof(write_buf), fp);

// 正确写法
fwrite(write_buf, sizeof(char), strlen(write_buf), fp);
```

## 表格

对比、参数、引脚、考点——能用表格就别写大段文字。表头简洁，单元格精炼。

## 引用块 `>`

放报错原文、重要提示、datasheet 摘录。不要用来放普通正文。

```
> 此文件是二进制文件或使用了不受支持的文本编码
```

## 笔触

- 平实口语，说人话。
- 长解释后接一句短句收束（「就这一个参数的区别。」）。
- 技术词用代码格式（`sizeof`、`fwrite`、`DMA`），正文中文。
- 不啰嗦：一个点讲清就过，不重复、不绕。

## 收尾

文末给「要点速查」表格，浓缩全文考点，方便读者和未来的自己快速回顾。

写完通读一遍，命中以下任何一条就改：

- ❌ 煽情升华：「让我们一起来探索」「开启一段旅程」「赋能 / 抓手 / 闭环」
- ❌ 工整排比、对仗堆砌、每段强行三段式
- ❌ 空洞强调：「非常重要」「至关重要」「不可或缺」「极其」
- ❌ 滥用 emoji、标题党
- ✅ 正面范例：「就这一个参数的区别。」「排查过程中发现教程中的一个错误。」——短、直接、有信息密度
