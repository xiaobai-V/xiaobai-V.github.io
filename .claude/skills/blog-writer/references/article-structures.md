# 文章骨架（5 类）

skill 按草稿内容自动判断属于哪类，套对应骨架。

> 骨架是「参考」不是「模板」——内容不够的段直接省，不强凑。一篇也可以混用多类（比如项目连载里夹一段踩坑）。

## 1 踩坑记录

适用：调试中遇到的问题、报错、意外行为。

**范例**：`content/Linux/sizeof vs strlen：从一次 fwrite 踩坑说起.md`

骨架：
1. **起因**：现象 / 报错是什么
2. **问题代码**：错误写法 vs 正确写法对比
3. **根因分析**：分小节深挖（3.1、3.2、3.3…）
4. **要点速查**：表格浓缩考点
5. **参考代码**：完整可运行的代码

## 2 外设 / 知识讲解

适用：介绍某个模块、外设、协议、概念。

**范例**：`content/项目/PN532驱动库移植_基于SMT32L4/PN532模块基本介绍和接线说明.md`

骨架：
1. **概述 / 特点**：这是什么，能干什么
2. **关键参数**：模式、引脚、寄存器、时序（多用表格）
3. **接线 / 配置**：具体怎么连、怎么配（表格）
4. **用法**：示例代码或操作步骤

## 3 项目连载

适用：一个项目的系列记录，每篇一个子主题。

**范例**：`content/项目/PN532驱动库移植_基于SMT32L4/` 系列

骨架：
1. **背景目标**：项目要解决什么
2. **本篇子题**：这篇聚焦哪个子任务
3. **问题与解决**：遇到的坑和怎么填的
4. **成果 / 代码**：阶段性产出

放对应项目子目录（如 `content/项目/<项目名>/`）。

## 4 随笔 / 方法论

适用：技术思考、学习方法、通用解法。

**范例**：`content/随笔/红蓝标记法：二分查找万能解法.md`

骨架：
1. **痛点**：要解决什么问题
2. **思路**：核心 idea
3. **步骤 / 实例**：怎么用，配例子
4. **要点**：浓缩成几条

## 5 工具 / 环境教程

适用：开发环境搭建、工具配置。

**范例**：`content/工具与方法/STM32开发环境搭建-VSCode+CMake+GCC.md`

骨架：
1. **为什么用**：选型理由
2. **装什么**：依赖和软件清单
3. **怎么配**：配置步骤（命令 / 配置块）
4. **验证**：怎么确认配通了
